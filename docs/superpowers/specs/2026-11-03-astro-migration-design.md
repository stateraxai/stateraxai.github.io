# 随机幂等：Astro 迁移方案

## 目标与边界

把 https://stateraxai.github.io/ 的现有静态网站迁移到 Astro 静态构建，为后续 Markdown 写作建立文章目录与详情页面。当前没有正式文章，迁移后仍显示真实的空状态，不把演示内容作为正式文章发布。

保留首页与 /about/ 地址、现有内容、Logo、深浅色主题、访问者本地日期与星期、像素逐字标题、公众号居中弹窗、手机布局及页脚。当前不接入 Pages CMS，不购买域名、不使用付费服务、不添加数据库、登录系统或评论系统。

## 方案选择

1. 推荐：Astro 原生组件 + Markdown 内容集合。保留现有 CSS 与交互，提取共享布局；文章由结构化内容自动生成。依赖较少，方便后续接 Pages CMS。
2. 采用现成 Astro 博客主题：起步快，但会重做已确认外观，增加主题适配工作。
3. 同时接入 Astro 和 Pages CMS：一步提供网页编辑，但需要 GitHub App 授权，两个系统一起排错，不适合作为本次首阶段。

本方案采用第一种。

## 页面与文件

- `src/layouts/SiteLayout.astro`：公共页面外壳、元信息、共享样式与脚本。
- `src/components/`：页头、导航、页脚和可复用文章列表。
- `src/pages/index.astro`：保留首页，文章区自动读取已发布文章。
- `src/pages/about.astro`：保留关于页面及二维码弹窗。
- `src/pages/articles/index.astro`：完整文章列表，零文章时展示空状态。
- `src/pages/articles/[...id].astro`：文章详情静态路由，包含标题、日期、摘要、正文和返回文章列表入口。
- `src/content/articles/`：Markdown 文章目录。
- `src/content.config.ts`：字段校验与内容加载。
- `public/`：Logo、二维码和公共图片；`src/styles/` 与 `src/scripts/` 保存原有样式和交互。
- `docs/`：写作、预览、发布与回退说明；文章模板放在内容集合之外，避免当作文章生成。

首页导航保持首页、文章、项目、随想、关于顺序。文章导航转向 /articles/；首页仍有文章目录入口。项目、随想本次保留空状态和原有锚点，不创建虚构内容。

## 文章字段与发布规则

字段为 `title`（必填）、`description`（必填）、`date`（必填，YYYY-MM-DD）、`draft`（默认 true）、`tags`（默认空数组），可选封面及其替代文字。文件名采用稳定英文短名，生成 /articles/短名/，文件名变更意味着网址变更。

开发预览允许查看草稿，并明确显示“草稿，仅本地预览”。生产构建的首页、文章列表与详情路由统一过滤 draft=true 的内容，避免通过直接地址访问草稿。日期按文章标注的日历日期展示，避免时区偏移。未到日期不隐式定时发布；明确以 draft 字段控制。

草稿过滤只控制网站展示。公开 GitHub 仓库中的源文件和历史仍公开，未确认公开的稿件不能提交到远程仓库。只在本地使用的试验文章在测试后移除，正式内容目录保持无文章状态。

## 构建与部署

采用当前稳定 Astro 版本并锁定依赖，兼容已安装的 Node 环境，记录受支持 Node 版本。输出静态 HTML 到 dist/；site 设置 https://stateraxai.github.io，根域名站点不设置仓库名 base。

准备 GitHub Actions：拉取源码、安装锁定依赖、校验与构建；合并 main 后发布 dist/ 到 GitHub Pages。迁移期间不修改生产 main，也不切换线上 Pages 来源。用户确认预览并明确同意发布后，才合并迁移分支并将 Pages 来源由分支发布切换到 GitHub Actions。

## 验收

1. Astro 构建成功，首页、关于页、文章列表页面均生成。
2. 无文章时所有入口正常，页面无虚构文章或失效链接。
3. 临时 Markdown 验证：非草稿可生成详情并进入列表；草稿可在开发环境查看，生产列表和路由均排除。
4. 验证中文、代码块、图片、长链接及文章日期展示。
5. 复查主题记忆、日期与星期、像素动画、减少动态效果设置、二维码弹窗键盘关闭与焦点返回。
6. 手机与桌面预览无横向溢出；本地资源与内部链接检查通过。
7. 提供本地预览地址和逐步写作说明，等待用户确认后再发布。

## 回退

迁移和上线分开。上线前保留当前生产提交与部署配置记录；若上线后异常，恢复上一静态版本及其分支发布配置。日常更新使用独立分支预览，确认后合并 main；避免直接改生产分支和强制覆盖历史。
